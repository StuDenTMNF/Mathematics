# Математическая модель игры с таймером 

В данном документе описывается математика игры Таймер. Модель основана на составлении таблиц для игры.

Сама игра делится на раунды.
1. Человек ставит определенную сумму.
2. Играет против бота.
3. Получает $S = S0 * K$. Если проиграл - не получает ничего.
4. Человек ставит определенную сумму...

---

## 1. Функции и генерация ошибок

Для симуляции механики остановки таймера используются два разных статистических распределения. Нормальное и экспоненциальное.

### 1.1 Модель ошибки человека (Нормальное распределение)
Человека мы представляем с помощью **Нормального распределения**.

* **Параметр:** $\sigma$ (Сигма) — стандартное отклонение (измеряется в секундах).
* **Смысл:** Это показатель "разброса" реакций или **неточности** игрока. Чем меньше $\sigma$, тем у́же колокол распределения и тем выше навык человека. Сигма измеряется в секундах.

### 1.2 Модель ошибки бота (Экспоненциальное распределение)
Для бота используется **Экспоненциальное распределение**. Оно гарантирует, что бот часто бьет близко к цели и никогда не совершает абсолютно неадекватных ошибок на пустом месте.

* **Параметр:** $\alpha$ (Альфа) — интенсивность распределения.
* **Смысл:** Это показатель **точности** бота. Чем больше $\alpha$, тем меньше его средняя ошибка (которая математически равна $1/\alpha$). Например, при $\alpha=2.0$ средняя ошибка составит $0.5$ секунды.

## 2. Математика игрового раунда

Каждый игровой раунд просчитывается строго аналитически. Логика расчета состоит из четырех последовательных шагов.

### Шаг 1: Бросок RNG
Система генерирует случайное число $U$ в диапазоне от $0$ до $1$. Это генератор случайностей, который определяет насколько удачно сыграет бот в текущем раунде.

### Шаг 2: Вычисление отклонения бота
Случайное число $U$ переводится в отклонение бота в секундах ($X_{bot}$) по формуле:
$$X_{bot} = -\frac{1}{\alpha}\ln(1 - U)$$

### Шаг 3: Вычисление вероятности победы человека
Теперь система знает, насколько ошибся бот. Чтобы человек победил, модуль его собственной ошибки должен быть меньше, чем $X_{bot}$. Вероятность этого события вычисляется через функцию ошибок (Error Function, `erf`), в которую подставляется результат бота и навык человека:
$$P(\text{победа}) = \text{erf}\left(\frac{X_{bot}}{\sigma\sqrt{2}}\right)$$

Об этом можно подробнее почитать в любом учебнике для вузов по статистике.

### Шаг 4: Формирование коэффициента выплаты
Каждый раунд расчитывается с учетом RTP = 95%. Коэффициент $K$, который будет выплачен игроку в случае успеха, рассчитывается так:
$$K = \frac{RTP}{P(\text{победа})}$$

Таким образом, мы еще и указали, что события между собой независимы, что вообще соответствует изначальной логике игры.

## 3. Пример полного цикла

Представим стандартную настройку системы:
* Целевой $RTP = 95\%$ ($0.95$)
* Точность бота $\alpha = 2.0$
* Навык целевого игрока $\sigma = 0.5$

**Ход раунда:**
1. Сервер генерирует случайное число: $U = 0.45$.
2. Вычисляется ошибка бота: $X_{bot} = -\frac{1}{2.0}\ln(1 - 0.45) \approx 0.298$ секунд.
3. Вычисляется вероятность того, что средний игрок остановит таймер точнее, чем $0.298$ секунд: 
   $P = \text{erf}\left(\frac{0.298}{0.5 \cdot 1.414}\right) \approx 0.448$ (или $44.8\%$).
4. Вычисляется итоговый множитель для этого раунда: 
   $K = \frac{0.95}{0.448} \approx 2.12$.

**Итог:** На экране игрока появляется коэффициент **x2.12**. Чтобы забрать этот выигрыш, игроку нужно нажать на кнопку так, чтобы отклонение таймера составило менее $0.298$ секунд в любую сторону.

## 4. Архитектура применения модели

Подобная математическая модель рассчитана на двухэтапное использование в архитектуре реальной игры для снижения нагрузки на сервер:

1. **Аналитический этап (Предрасчет):** До запуска игры вычисляется огромная таблица (сотни тысяч строк), содержащая готовые связки «Случайное число $U$ $\rightarrow$ Ошибка бота $X_{bot}$ $\rightarrow$ Коэффициент $K$». Эти данные сохраняются в csv файл. Это сделано для того, чтобы можно было промоделировать для разных $\sigma$ и $\alpha$, если конечная таблица не устраивает.
2. **Игровой этап (Движок):** Во время реальной сессии сервер не вычисляет логарифмы и функции ошибок. При старте раунда он просто генерирует случайное число, берет из готовой таблицы соответствующие значения $X_{bot}$ и $K$, показывает их клиенту и ждет результат нажатия кнопки человеком для определения победителя.
